# СытоМастер

Сайт подбирает ужин из продуктов дома с учётом времени, бюджета на порцию и ограничений питания. Из рецепта можно перейти к пошаговой готовке, включить таймер и составить список покупок.

## Запуск

Распакуйте всю папку и откройте [index.html](index.html). Страницы уже собраны. Для подбора, таймеров и корзины нужен включённый JavaScript. Интернет не требуется.

Для демонстрации всего сценария с сохранением между страницами удобнее открыть терминал в папке с этим README и запустить локальный сервер. Достаточно Python 3.10 или новее, зависимости устанавливать не нужно.

```sh
python server.py --port 8000
```

Откройте [сайт на компьютере](http://127.0.0.1:8000). Сервер принимает соединения на этом компьютере. Остановка — Ctrl+C. После изменений исходных шаблонов, фрагментов или каталога пересоберите четыре HTML-страницы и браузерную копию данных командой `python build.py`. После изменения каталога перезапустите и работающий сервер.

Контурные иконки собраны в локальном [SVG-спрайте Lucide](static/icons/lucide.svg). Сборка встраивает его в HTML, чтобы пиктограммы работали при прямом открытии файла. [Лицензия](static/icons/LUCIDE-LICENSE.txt)

## Экраны и состояния

| Страница | Что можно сделать |
|---|---|
| [Главная](index.html) | Ввести продукты и выбрать их из подсказок, задать время, бюджет, приоритет, исключения и требования к составу. До подбора видна случайная тема с двумя блюдами. Стрелки переключают темы. Ниже расположен весь каталог с поиском по названию. |
| [Рецепт на примере риса с курицей](recipe.html?id=rice) | Прочитать состав и шаги, выбрать от одной до восьми порций, отметить продукты дома, отправить недостающее в корзину. Таймеры есть у шагов с указанной длительностью. В конце можно перейти к другому блюду с общим ингредиентом. |
| [Корзина](cart.html) | Посмотреть список продуктов для выбранных блюд, суммарное количество общих ингредиентов и расчёт расходов. Отметить купленное, удалить позицию или отменить последнее удаление. |
| [Состояния](states.html) | Проверить на одном экране первый визит, ожидание, точный и частичный результаты, пустую выдачу и ошибку. Это экран проверки интерфейса. |

Кнопка «Подобрать» становится активной после выбора первого продукта. Точный результат предполагает, что все необходимые продукты есть дома. При частичном совпадении у каждого блюда перечислено, что докупить. Выход за лимит времени или бюджета требует отдельного действия пользователя, а в результате указана величина отклонения. Исключения и обязательные требования к составу действуют в обоих режимах. При ошибке загрузки каталога доступны повтор и сохранённые условия. После отказа модели сайт продолжает подбор по локальной базе.

## Структура передачи

- [pages](pages) содержит исходные страницы, [partials](partials) — общие компоненты и фрагменты загрузки, пустого, успешного, частичного и ошибочного результата. Готовые страницы для открытия лежат рядом с README.
- [static/css/tokens.css](static/css/tokens.css) содержит палитру, назначение цветов, шкалу размеров и типографику. В [DESIGN.md](DESIGN.md) описаны визуальные правила, в [AGENTS.md](AGENTS.md) — порядок изменения и проверки проекта. Результаты проверки приведены в [qa.md](qa.md).
- [static/data/recipes.json](static/data/recipes.json) — исходная база. Сборка создаёт из неё `catalog.js`, который открывается и через `file://`. В [catalog-info.json](static/data/catalog-info.json) находятся ценовой справочник, единицы измерения и методика расчёта.
- [static/js/search-engine.js](static/js/search-engine.js) ищет совпадения и проверяет ограничения. Действия формы обрабатывает `picker.js`, карточки и каталог выводит `site.js`, приготовление и покупки обслуживает `cooking.js`. [server.py](server.py) раздаёт те же статические файлы и поддерживает дополнительное ранжирование через Ollama.

## Контракт каталога

Авторский учебный каталог содержит **520 записей в восьми семействах**. Есть восемь базовых рецептур и 512 рассчитанных вариантов. Для каждого семейства сочетаются восемь подходящих добавок и восемь овощных компонентов. У варианта свои количества, обработка, шаги и расчёт. Используются восемь изображений подачи. На странице варианта подпись сообщает, какому семейству принадлежит иллюстрация.

| Поля рецепта | Тип, единицы и пример | Источник |
|---|---|---|
| `id`, `name`, `description` | Строки. Например, `rice`, «Рис с курицей» и описание готового блюда | Каталог |
| `family`, `familyLabel`, `isVariant`, `featured` | Идентификатор и название семейства, два логических признака. У основного блюда `rice`, «Рис», `false`, `true` | Редакционная структура каталога |
| `servings`, `minutes`, `price` | Целые числа. У риса с курицей 2 порции, ≈30 минут, ≈114 ₽ за порцию | Выход рецептуры, оценка времени, сумма стоимости продуктов для всей партии, делённая на количество порций и округлённая |
| `hearty`, `tags` | Целая редакционная оценка сытости 1–3 и массив признаков состава. У риса с курицей `3`, `dairy-free`, `egg-free`, `gluten-free` | Состав рецептуры и редакционная шкала. Калорийность не рассчитывается |
| `source`, `image`, `imageAlt`, `imageCaption` | Источник рецепта, имя файла WebP, описание и подпись иллюстрации | Авторский каталог и изображения проекта |
| `ingredients`, `steps` | Массив ингредиентов и упорядоченный массив этапов | Рецептура конкретной записи |
| `ingredients[].id`, `.name`, `.aliases`, `.pantry` | Строковый ключ, подпись, массив синонимов, признак домашнего запаса. Для `chicken` ввод «курица» находит куриное филе | Словарь каталога, 38 продуктов. К домашнему запасу отнесены вода, соль и растительное масло |
| `ingredients[].quantity`, `.unit`, `.amount`, `.cost` | Число, единица, готовая подпись, расчётные рубли **на исходную партию**. Для куриного филе в `rice` это 300, «г», «300 г», 174 ₽ | Учебный справочник и количество в рецептуре. При изменении порций количество и стоимость пересчитываются пропорционально |
| `steps[].title`, `.text`, `.minutes` | Заголовок действия и инструкция строками, длительность таймера целым числом минут. На шаге «Сварите рис» — 12, на шаге без таймера — 0 | Инструкция. Общее время может включать параллельные действия |

Возможные признаки состава — `vegan`, `vegetarian`, `dairy-free`, `egg-free`, `gluten-free`. Метки учитывают перечисленные ингредиенты. Аллергены в упаковке и перекрёстный контакт проверяют по маркировке производителя. Подтверждений халяль в базе нет, поэтому выбор этого обязательного условия даёт пустой результат. Учебные цены оценивают использованное количество, а не чек за полные упаковки. Синхронизации с магазинами нет.

## Контракт подбора

| Данные | Представление и источник |
|---|---|
| Продукты, исключения, питание | `products`, `excluded`, `diet` — массивы строковых идентификаторов из пользовательской формы. Выбранный продукт должен встретиться в составе блюда. Точное совпадение дополнительно требует весь состав с учётом домашнего запаса. Исключения проверяются и среди домашних запасов. |
| Время, бюджет, приоритет | `time` — минуты, `budget` — ₽ за порцию, ноль снимает соответствующий лимит. `mode` принимает `fast`, `cheap` или `hearty`. `relax` — явное согласие посмотреть блюда за пределами лимитов, `submitted` — признак выполненного подбора. |
| Результат | `state`, `title`, `notice`, `groups`, `actions`. У группы есть заголовок и `items` с идентификатором рецепта и проверяемой причиной. Показывается до пяти подходящих блюд. Предпочтение отдаётся разным семействам, если позволяет доступный выбор. |
| Хранение | На одном адресе браузер хранит настройки в `syto-picker-v1`, покупки в `syto-cart-v1`, таймеры в `syto-timers-v1`. Данные остаются на устройстве. В приватном режиме и при запрете хранилища сохранность между открытиями зависит от браузера. |

При прямом открытии файлов `file://` браузер может изолировать хранилища отдельных страниц. Выбранные продукты и ограничения передаются из главной в ссылку рецепта. Для общего состояния корзины и таймеров между страницами используйте локальный сервер. Таймер сверяет время окончания при возвращении на сайт. Уведомление появляется внутри открытой страницы.

## Дополнительное ранжирование Ollama

Основной поиск работает с локальным каталогом. Если точных совпадений нет, сервер может поручить уже установленной модели выбор вариантов из списка подходящих кандидатов. Рецепт и его шаги берутся из базы. На сервере повторно проверяются состав, теги и лимиты, в ответе принимаются только известные идентификаторы из запроса. Объяснения докупки и отклонения рассчитывает подбор по фактическим данным блюда.

В PowerShell запустите локальный сервис Ollama и посмотрите `ollama list`. Если в списке есть, например, `qwen2.5:7b`, следующий запуск включает именно её. Для другой установленной модели подставьте точное имя из первого столбца.

```powershell
$env:SYTO_OLLAMA_MODEL = "qwen2.5:7b"
$env:SYTO_OLLAMA_URL = "http://127.0.0.1:11434"
python server.py --port 8000
```

`SYTO_OLLAMA_URL` необязателен, по умолчанию используется адрес из примера. Сервер публикует относительный `POST /api/rank` в конфигурации браузера только при заданной модели. Запрос дополнительно содержит `ids` (до 12 уже отобранных кандидатов), ответ — `{"ids":[...]}` (до пяти). При таймауте, недоступной модели или некорректном ответе интерфейс сообщает об этом и показывает результат локального поиска. В архив входит интеграция, веса модели устанавливаются отдельно. При проверке вместо весов использовался тестовый HTTP-ответчик по контракту Ollama; качество ответов конкретной модели нужно оценить после подключения. [Формат ответа Ollama](https://docs.ollama.com/capabilities/structured-outputs)
